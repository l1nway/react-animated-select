# scripts

Repo tooling run from the root `package.json`.

## Bundle size

`size.js`, run by `npm run size` (root) and by CI right after the package build and `check:pack`. It measures the **built package**, so run `npm run build -w packages/react-animated-select` first; a stale `dist` gives stale numbers.

- **Why here, not in the package:** it is repo tooling next to `checkPack.js`, it measures the package from outside as a consumer (`react-animated-select` resolves through the workspace link in the root `node_modules` to `dist/index.js` by the `exports` map), and nothing in the package folder may ship (`files` whitelist). `vite` and `rollup` come from the package's dev dependencies, hoisted to the root; `webpack`, `css-loader` and `mini-css-extract-plugin` are root dev dependencies (owner-approved 2026-10-07, tooling only, never in the package).
- **Consumer build:** Vite `build()` with a virtual entry `export {…} from 'react-animated-select'`, `configFile: false`, production mode (so `process.env.NODE_ENV` is replaced and the dev branches drop), default minifiers (esbuild for JS and CSS), `react`, `react-dom` and their subpaths external, `preserveEntrySignatures: 'strict'` (the exports stand in for an app that uses them). The installed Vite 7 bundles with **Rollup 4**; rolldown is not installed, so the numbers are Vite + Rollup, not rolldown-vite (the method of the 2026-10-04 numbers). The header line prints the exact Vite and Rollup versions.
- **Webpack consumer:** the same entries and checks through webpack 5 in production mode (`usedExports`, `sideEffects`, module concatenation, terser for JS), `react`, `react-dom` and their subpaths external as ES modules, `.css` through `css-loader` and `mini-css-extract-plugin` into a CSS file (as an app that ships CSS files would). It resolves the package by the `import` condition of the `exports` map, so it reads the same `dist/index.js`. The entry and the output go to a temp folder (`os.tmpdir()`), removed after each entry; `resolve.modules` adds the root `node_modules`, because the entry file sits outside the repo.
- **Webpack traps:** the entry must be a library (`output.library.type: 'module'` with `experiments.outputModule`), otherwise its exports are unused and webpack shakes away the whole package (0 bytes of JS, which still pass an absent-marker check; the present-marker check catches it). With module output webpack names the file `main.mjs`, not `.js`. CSS is not re-minified (no `css-minimizer-webpack-plugin`): the package's CSS is already minified by its build, and webpack only adds a newline per CSS module (+3 to +5 bytes against Vite). The CSS comes out in import order (`theme.css` before `base.css`, as `select.js` imports them); the `@layer rac.base, rac.theme;` at the top of every file keeps the cascade right. Probed on 2026-10-07: with `optimization.sideEffects: false` webpack keeps `chip.css` without `chips` (its JS is still dropped by `usedExports`), and the CSS marker check fails as it should.
- **No `style.css` import:** the root `README.md` tells ES-build consumers that the CSS loads by itself; `style.css` is only for CommonJS and setups that skip CSS imports. Importing it would also hide the tree-shaking result (it holds every rule, chips included).
- **Entries:** `core` (`Select`, `Option`, `OptGroup`), `chips`, `paging`, `all` (plus `defineOption`). Columns: JS min, JS gzip, CSS min, CSS gzip, bytes; gzip is `zlib` level 9 over the concatenated chunks and CSS assets.
- **Checks:** a marker string unique to each plugin (`rac-chip-slot` for `chips`: `chip.jsx` and `chip.css`; `special-load-more-id` for `paging`) must be absent from JS and CSS when the plugin is not imported, and present in JS when it is (so a renamed marker cannot pass silently). Every entry must contain the core CSS (`--rac-duration-fast` from `base.css`, `--rac-tint-1` from `theme.css`): Rollup, rolldown and webpack drop the CSS of a side-effect-free module whose bindings are unused, which once shipped an unstyled Select (`packages/react-animated-select/src/README.md`, Styles Layer).
- **Budgets:** `BUDGETS` holds bytes per entry in column order, set to the exact values of 2026-10-07; any byte over exits 1. They apply to the Vite build only. The webpack bytes are printed for information: they are deterministic (two runs identical), but a second budget would catch no package growth that the Vite budget misses, and would fail on every webpack or terser update in the lock with no change to the package. The webpack marker and core CSS checks do fail the run. A deliberate increase is raised by the owner, with the delta stated in the release; a decrease may tighten the budget. A new plugin adds its entry, marker and budget.
- **Not covered:** esbuild, which keeps every reachable CSS file by design, so its CSS result says nothing about the package.
- **Trap:** gzip bytes depend on the `zlib` build of Node; CI and the owner's machine both run Node 24. A one-off mismatch of a few bytes after a Node upgrade is the toolchain, not the package: re-measure on the CI Node before raising anything.
