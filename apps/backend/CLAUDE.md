# Backend

The LLM backend behind the demo's "Ask a question" (`POST /ask`). Express 5, CommonJS. Not an npm workspace: it keeps its own `package-lock.json`, so its deploy bundle is self-contained.

## Run

- `npm run dev:api` from the repo root (`npm run dev --prefix apps/backend`): builds the data, then starts `nodemon` on port 3000 (`PORT`).
- Install with `npm ci --prefix apps/backend`, never from the root.
- The demo dev server (`npm run dev` at the root) calls `http://localhost:3000/ask` (`apps/demo/.env.development`).

## Secrets

- `.env` is local and never committed. `.env.example` lists the keys the code reads (`PORT`, `GEMINI_API_KEY`, `GROQ_API_KEY`, `TRUST_PROXY`, `LIMIT_*`); keep it in sync when the code reads a new one.
- In production the keys live in the AWS service's configuration, never in git, GitHub or a deploy zip.

## Code and limits

- `src/index.js`: the Express app and `POST /ask`. `src/llm.js`: providers, model roles, routing and transcription. `src/limits.js`: rate limit and upload limits.
- Limits run before the body is read: one request in flight per IP, `LIMIT_PER_MINUTE` (5) and `LIMIT_PER_DAY` (50) per IP, `LIMIT_GLOBAL_PER_DAY` (2000) for everyone; over the limit → `429` with `Retry-After`. Counters live in memory, so they reset on restart and are per instance.
- Body limits: `prompt` at most 2048 characters, one `audio/*` file at most 1 MB; over → `413`.
- The client IP comes from `X-Forwarded-For` through `TRUST_PROXY` hops (default `2`: nginx on Elastic Beanstalk, then CloudFront). With a load balancer in front of nginx it is `3`. A wrong value either puts every visitor into one bucket or lets a client spoof its IP.
- A request aborts its LLM calls when the client disconnects or after 40 s (the site gives up at 45 s). Unreadable audio (Whisper `400`) returns `400`.
- **CORS** (`ORIGINS` in `src/index.js`) allows only `https://l1nway.github.io` and `http://localhost` / `http://127.0.0.1` on any port. It is not authentication (`curl` ignores it); the limits above are the real protection. A new site origin (custom domain, preview) must be added to `ORIGINS`, or browsers block its requests.

## Models

Free tiers of Groq and the Gemini API (AI Studio key), checked on 2026-10-05. `ROLES` in `src/llm.js` gives each role a list of models: the first `spread` take turns (load spreading), the rest are fallbacks in order. A model that fails is skipped for a while (`429`: its `Retry-After` or 60 s, `404`: 1 h, other: 15 s); when every model of a role is cooling, all are tried anyway.

| Role | Models | Why |
|---|---|---|
| router | `openai/gpt-oss-20b` → `qwen/qwen3.8-27b` → `gemini-3.5-flash-lite` → `gemini-3.1-flash-lite` | fastest (0.1–0.5 s), one-word output |
| docs, styling (~4k tokens) | `openai/gpt-oss-120b` ⇄ `qwen/qwen3.8-27b` → `gemini-3.5-flash-lite` → `openai/gpt-oss-20b` → `gemini-3.1-flash-lite` | Groq: 8k tokens per minute per model, so about two digest requests per model per minute; the turn-taking doubles that |
| codebase (~100k tokens) | `gemini-3.8-flash` ⇄ `gemini-3.6-flash` → `gemini-3.7-flash` → `gemini-3.5-flash` → `gemini-3.5-flash-lite` → `gemini-3.1-flash-lite` | only Gemini takes this context on a free tier; implicit caching covers ~94% of it on repeats (about 5–11 s per answer) |
| offtop | `qwen/qwen3.8-27b` → `gemini-3.5-flash-lite` → `openai/gpt-oss-20b` | small reply, kept off the router's quota |
| transcription | `whisper-large-v3` → `whisper-large-v3-turbo` | separate quotas; a vocabulary hint keeps library names spelled right |

- Gone or unusable on the free tier: `moonshotai/kimi-k2-instruct`, `qwen/qwen3-32b`, `llama-3.1-8b-instant` (Groq); every `gemini-2.5-*` (404 for new users), `gemini-3.1-pro-preview` / `gemini-pro-latest` (paid). `gemma-4-*` leak their reasoning into the text; `allam-2-7b` answers poorly.
- Gemini is called over REST (`fetch`, `v1beta generateContent`, `systemInstruction`, `thinkingConfig.thinkingLevel`); the archived `@google/generative-ai` SDK was removed. Groq reasoning: `reasoning_effort` (`gpt-oss`: `low`; `qwen3.8`: `none`).
- `docs` / `styling` answers that the digest cannot cover come back as `ESCALATE` and go to `codebase`.
- Re-check the model lists when a provider deprecates a model: `https://console.groq.com/docs/deprecations`, `https://ai.google.dev/gemini-api/docs/deprecations`. Gemini free quotas are visible only in AI Studio.

## Data

- The assistant's texts are `src/data/documentation.md`, `src/data/styling.md` and `src/data/prompts/*.md`. They are committed and owned by Gemini (root `CLAUDE.md`, "Model roles"; maintenance guide `KNOWLEDGE.md`). Claude does not edit them: it queues changes in `BUGS.md`, "Knowledge queue".
- `src/data/bundle.json` (the `codebase` context) is generated by `npm run build-data` (`scripts/bundle.js`): `index.d.ts`, the root `README.md`, `FEATURES.md` without "Planned" and demo notes, `STYLES.md`, `src/README.md`, then the source without comments, stamped with the package version. It is gitignored; rebuild it after a library change and before a deploy.
- `build-data` then runs `scripts/checkData.js`, a token-free check of the digests against `index.d.ts` and the library CSS; `npm run check-data` is the strict form (exit code 1 on any warning).

## Contract and links

- The request and response contract lives in `apps/demo/backend.md`.
- The backend relates only to the demo; it never imports the library (it only reads the library source to build its context).
- A backend change that affects the demo (contract, URL, behaviour) is made in `apps/demo` in the same change, or recorded in `apps/demo/SYNC.md`. If the task does not say which, ask the owner.
- Bugs found in the backend from the demo are recorded in `apps/backend/BUGS.md` ("Bugs") unless the owner approves an immediate fix.

## Deploy

Today the backend is uploaded to AWS as a manual zip. `.github/workflows/backend.yml` (manual trigger only) is a template for a CI deploy and is enabled after the AWS service, region and an OIDC role are set up.
