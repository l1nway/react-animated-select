# Backend

The LLM backend behind the demo's "Ask a question" (`POST /ask`). Express 5, CommonJS. Not an npm workspace: it keeps its own `package-lock.json`, so its deploy bundle is self-contained.

## Run

- `npm run dev:api` from the repo root (`npm run dev --prefix apps/backend`): builds the data, then starts `nodemon` on port 3000 (`PORT`).
- Install with `npm ci --prefix apps/backend`, never from the root.
- The demo dev server (`npm run dev` at the root) calls `http://localhost:3000/ask` (`apps/demo/.env.development`).

## Secrets

- `.env` is local and never committed. `.env.example` lists the keys the code reads (`PORT`, `GEMINI_API_KEY`, `GROQ_API_KEY`); keep it in sync when the code reads a new one.
- In production the keys live in the AWS service's configuration, never in git, GitHub or a deploy zip.

## Data

- `src/data/bundle.json` is generated by `npm run build-data` (`scripts/bundle.js`) from the library source in `packages/react-animated-select/src`. It is gitignored; rebuild it after a library change.
- `src/data/documentation.md` and `src/data/styling.md` are hand-written and committed.

## Contract and links

- The request and response contract lives in `apps/demo/backend.md`.
- The backend relates only to the demo; it never imports the library (it only reads the library source to build its context).
- A backend change that affects the demo (contract, URL, behaviour) is made in `apps/demo` in the same change, or recorded in `apps/demo/SYNC.md`. If the task does not say which, ask the owner.
- Bugs found in the backend from the demo are recorded in `apps/backend/BUGS.md` (created with its first entry) unless the owner approves an immediate fix.

## Deploy

Today the backend is uploaded to AWS as a manual zip. `.github/workflows/backend.yml` (manual trigger only) is a template for a CI deploy and is enabled after the AWS service, region and an OIDC role are set up.
